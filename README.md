# Sentellent Stock Analyst — Contextual Agentic AI Indian Equity Analyst (RAG)

Built for the Sentellent Full Stack AI SDE Intern hiring challenge.

## Architecture

- **Backend**: FastAPI + LangGraph agent, PostgreSQL + pgvector, Google OAuth/JWT auth
- **Frontend**: Next.js (App Router) + Tailwind, client-rendered (chat/dashboard), static export
- **Ingestion**: screener.in fundamentals scraper + Indian financial news RSS → chunk → embed → pgvector, idempotent + concurrency-safe via Postgres advisory locks
- **Agent**: LangGraph graph — persona memory update → intent routing → grounded/cited retrieval-QA or algorithmic (non-LLM) persona-based stock ranking
- **Deployment (default, $0)**: Render (free web service + free static site) + Neon (free Postgres/pgvector) — see below
- **Deployment (optional, costs money)**: Terraform for AWS (VPC, RDS, ECS Fargate, ALB, ECR, S3+CloudFront, Secrets Manager) — kept in `infra/terraform/`, not used by default
- **CI**: GitHub Actions (`.github/workflows/ci.yml`) runs backend/frontend checks on every PR

## Local development

```bash
cp backend/.env.example backend/.env      # fill in GEMINI_API_KEY, GOOGLE_CLIENT_ID/SECRET
cp frontend/.env.local.example frontend/.env.local
docker-compose up --build
```

Backend: http://localhost:8000 (docs at `/docs`)
Frontend: http://localhost:3000

Migrations run automatically on backend container start (`alembic upgrade head`).

## Deploying for free (Render + Neon) — the actual path used for this submission

Nothing below requires a credit card, and nothing here can silently start billing you —
both Render's free plan and Neon's free plan are hard-capped, not pay-as-you-go with a
card on file. Total cost: **₹0**.

**1. Database — Neon (free Postgres + pgvector, never expires)**

- Sign up at [neon.com](https://neon.com) (no card required), create a free project.
- Neon gives you a connection string immediately — pgvector ships as a supported extension;
  the app's own Alembic migration runs `CREATE EXTENSION IF NOT EXISTS vector` on first boot,
  so you don't need to do that by hand.
- Free tier: 0.5 GB storage, 100 compute-hours/month, compute scales to zero when idle. Plenty
  for a handful of followed stocks and a hiring-challenge review window.

**2. Backend + Frontend — Render Blueprint**

- Push this repo to GitHub.
- In the Render dashboard: **New → Blueprint**, pick this repo, and point it at
  `infra/render/render.yaml` (Render's default is a root-level `render.yaml`; this project
  keeps it under `infra/render/` instead, so select that path explicitly when prompted).
- Render provisions two free services: `sentellent-backend` (Docker web service) and
  `sentellent-frontend` (static site, built from the Next.js static export). Every push to
  `main` auto-redeploys both — this is what satisfies the challenge's "push to main →
  deploy automatically" requirement; no separate GitHub Actions deploy job is needed.
- Fill in the secrets Render prompts for (marked `sync: false` in `render.yaml`): your Neon
  `DATABASE_URL`, `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `GEMINI_API_KEY`. `JWT_SECRET`
  and `INTERNAL_REFRESH_TOKEN` are auto-generated by Render.

**3. Fix the URLs after the first deploy (same idea as updating a CloudFront domain post-`apply`)**

Render assigns your services' real `*.onrender.com` URLs on first deploy — `render.yaml`
guesses `sentellent-backend.onrender.com` / `sentellent-frontend.onrender.com`, which is only
correct if those exact names were free. Once deployed, check the dashboard for the real URLs
and, if they differ, update in the Render dashboard and redeploy once:
- Backend env var `OAUTH_REDIRECT_URI` → `https://<your-actual-backend-url>/api/auth/google/callback`
- Backend env var `FRONTEND_URL` → `https://<your-actual-frontend-url>`
- Frontend env var `NEXT_PUBLIC_API_URL` → `https://<your-actual-backend-url>`

Then add that same `OAUTH_REDIRECT_URI` to the Google Cloud Console's authorized redirect URIs.

**4. Scheduled news refresh — GitHub Actions cron (also free)**

Render's free web service sleeps after 15 minutes of inactivity, so the in-process
APScheduler job can't be trusted to fire on a sleeping process. Instead, a scheduled GitHub
Actions workflow (`.github/workflows/news-refresh.yml`) hits an authenticated endpoint hourly
— GitHub Actions cron is free (public repos: unlimited; private repos: 2,000 min/month, and
this job uses seconds of that). Set these two **repo secrets** (Settings → Secrets → Actions):
- `BACKEND_URL` — your Render backend URL
- `INTERNAL_REFRESH_TOKEN` — copy the value Render auto-generated for that env var

**5. Free-tier tradeoffs to know about (and be ready to explain in your interview)**

- Backend cold starts: the free web service sleeps after 15 min idle, first request after
  that takes ~30-60s. The scheduled refresh workflow also has the side effect of keeping it
  warmer than it'd otherwise be.
- Neon storage cap (0.5 GB) is enough for a modest number of followed stocks + news history,
  not for scaling to thousands of users — a real production deployment would move to a paid
  tier or back to the AWS Terraform path in `infra/terraform/`.
- No custom domain / ACM cert needed — Render's `*.onrender.com` subdomains get free HTTPS
  automatically.

## Deploying to AWS (optional — this costs real money, not used by default)

The Terraform in `infra/terraform/` still provisions the full AWS stack described in the
architecture section above, and `.github/workflows/deploy-aws-optional.yml` can deploy it —
but that workflow is intentionally **not** wired to run on push (only manual
`workflow_dispatch`), so it can't fire by accident. RDS, ALB, and Secrets Manager all cost
money outside/alongside any AWS free-tier allowance. Only use this path if you decide to pay
for it on purpose; it needs `AWS_ACCESS_KEY_ID`/`AWS_SECRET_ACCESS_KEY` repo secrets this repo
does not set up for you, plus `DB_PASSWORD`, `JWT_SECRET`, `GEMINI_API_KEY`,
`GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`.

**Note:** this Terraform has not been run against a live AWS account — checked for structural
correctness (brace balance, resource wiring) but not `terraform validate`/`plan`.

## What's implemented vs. remaining

Implemented: auth, follow-triggered + scheduled ingestion (idempotent, dedup, advisory-locked), LangGraph RAG chat with citations and INR grounding, persona extraction from chat, algorithmic (non-LLM) recommendation scoring including the growth-rate boost for aggressive personas, a genuinely free deployment path (Render + Neon, auto-deploy on push, free scheduled refresh via GitHub Actions), an optional/paid AWS Terraform path kept for later, GitHub Actions CI, pytest coverage on the pure-logic pieces (chunking/dedup/scoring) plus the ingestion race-condition and news-matching paths (mocked, since there's no live Postgres in CI yet).

Not yet built: hybrid retrieval/re-ranking beyond cosine similarity, LangGraph checkpointing/streaming, rate limiting, load testing, a proper integration test suite for the DB-touching code against a real Postgres+pgvector instance (current tests mock the DB session — good for logic correctness, not a substitute for testing against real Postgres concurrency/locking behavior).

## Before your next deploy

1. **Rotate your Google OAuth client secret and Gemini API key.** Your uploaded `.env` had live secrets, and a placeholder-looking value in `backend/.env.example` turned out to actually be a real Google OAuth client ID/secret — it's been replaced with a clearly-fake placeholder here, but rotate both credentials in their respective consoles regardless, since they've now passed through chat history.
2. Deploy the Render Blueprint (see above), then fix up `OAUTH_REDIRECT_URI` / `FRONTEND_URL` / `NEXT_PUBLIC_API_URL` to match your actual assigned `*.onrender.com` URLs, and add the redirect URI to the Google Cloud Console's authorized redirect URIs.
3. Set the `BACKEND_URL` and `INTERNAL_REFRESH_TOKEN` GitHub repo secrets so the free scheduled news-refresh workflow can actually reach your backend.
4. Double check your real `GEMINI_API_KEY` — Google AI Studio keys normally start with `AIzaSy...`; if yours starts with something else, verify it's the correct key before it goes into Render.
